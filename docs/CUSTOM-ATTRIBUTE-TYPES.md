# Boolean and enum rig controls

Select any eligible object, joint or IK handle and choose **Edit > Add Attribute…**. The existing dialog now offers Float, Boolean and Enum. Float fields and files keep their previous behavior. Boolean uses Off/On and a checkbox in Properties; Enum uses named choices. Both retain Keyable and the saved Lock/Unlock controls. Owner identity remains the transform for a shape, or the joint/IK ID directly.

For an enum, edit the entry labels, add entries, or use the up/down controls to set their display order. Each entry has a stable ID and a permanent numeric code. Reordering does not renumber codes: an animated Grip choice remains Grip after moving it to the top of the menu. Renaming changes only its label. Newly added entries receive new codes; deleted codes cannot be reused. SDK pickers show choice names, including stored key rows, so rigs do not require guessing numeric indices.

Choose a Boolean/Enum value in Properties and click its diamond to set a time key. Each choice gesture and each key is one undo step. Numeric fields still support live typed/MMB preview, exact Escape cancellation and one release commit. Native choice menus cancel before accepting a selection with Escape; accepted checkbox/menu changes undo normally. Pending numeric and discrete values survive editing/keying another custom channel at the same frame; time scrubbing, playback and scene replacement retain the established draft-clear behavior. Drafts never become authored data by evaluation.

Boolean/Enum time curves and SDK relationships involving them use **Step** interpolation. Between keys the previous state holds; endpoint values hold outside the keyed range. SDK can drive multiple joint rotations from a state or drive another discrete attribute from a continuous driver. Invalid/fractional/removed state values and non-Step curves are rejected atomically, including through Graph edits and MSB opens. Graph labels show the attribute type.

Discrete layer values are categorical. An enabled contribution with weight **at least 0.5** replaces the state below it; lower weights leave that state intact. Later eligible contributions win. Additive layers use this same categorical override behavior for discrete channels, analogous to the editor's existing visibility special case. Muting, solo and animated layer weights retain their existing rules. Keying a masked layer or a layer below the threshold rejects with the existing no-influence feedback. Float layer blending and inverse keying are unchanged.

Use **…** to edit a definition. Removing an entry used by a time key or SDK driver/output rejects with feedback. Current/default must also identify an existing choice; set them to another choice before removing that entry. Type changes on a referenced definition reject until its time/SDK references are removed. Locked definitions must be unlocked first. **Delete Attribute and References** remains the explicit one-undo cascade for an entire definition. Object deletion cleans its definitions/references. Existing Mirror Joint Subtree copies definitions with fresh attribute and enum entry IDs, preserves their code meanings, and keeps time/SDK curves on the source as before.

Open [the original switch example](../examples/custom-types-sdk.msb): one rational NURBS control, three joints, Boolean `enabled`, enum `poseMode`, seven time keys and two SDK relationships. Its states hold deterministically at fractional, random and backwards times. It embeds no downloaded assets. Regenerate with `node scripts/create-custom-types-example.mjs`.

## Representation and limits

Current scene/archive versions remain 2/1. Existing Float definitions omit `type` or use `float`. Boolean definitions add `type:"boolean"`, with numeric current/default 0 or 1. Enum definitions add `type:"enum"`, `entries:[{id,name,value}]` and `nextValue`. Entries are addressed by stable IDs; their immutable numeric codes bridge the existing animation/SDK scalar interfaces. UI array position is never a reference. No legacy migration or extra evaluator is added.

An enum has **1–64** entries. Names are trimmed, nonempty, at most 80 characters and unique case-insensitively per definition. IDs follow existing scene ID validation. Codes are unique nonnegative integers through 1,000,000; `nextValue` is monotonic and greater than every current code. Boolean/Enum definitions do not accept numeric min/max. Existing 64 attributes per owner, 10,000 total, key/relationship limits and Float ±1e12 bounds remain. Work is bounded by these limits and reuses the compiled channel/layer plan. Verification uses original small rigs and does not claim large-rig throughput.

## Maya mapping and provenance

Autodesk's [custom attribute workflow](https://help.autodesk.com/cloudhelp/2025/ENU/Maya-Basics/files/GUID-EC37B453-05D8-4A60-B6A9-57895363759E.htm) defines Boolean as an on/off switch and Enum as choices. The official [addAttr reference](https://help.autodesk.com/cloudhelp/ENU/MayaCRE-Tech-Docs/Commands/addAttr.html) permits explicit numeric enum values. Musubi retains the owner-requested **Edit** placement and common Extra Attributes, native focus/Enter/Escape, existing numeric scrubbing and saved Lock/Unlock. Permanent codes and explicit HTML options avoid renumbering or phantom choices when labels/order change. Categorical layer selection is an intentional browser/editor adaptation, documented above; no fractional enum states are exposed.

Implementation, tests and procedural fixture are original. Existing Three.js 0.180.0, Spark 2.4.0, Lucide lock icons and the project's channel/layer/SDK/Graph/archive/history modules are reused. No new dependency, provider, model, external dataset or proprietary artwork/code was added. Introducing a separate typed animation framework was unnecessary and would duplicate these contracts. Numeric examples remain readable without regeneration.
