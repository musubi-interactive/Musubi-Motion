# Bridge mesh boundary loops

Open **Modeling → Mesh Tools**, select a mesh, and switch to **Edge** mode. Pick one boundary edge on each loop using the viewport or the component list. Click **Select Boundary Loops** to expand the picks, then click **Bridge** under **Edit Topology**. You can also select both complete loops directly.

- **Direction** shows whether the target loop's canonical vertex order needs to run forward or in reverse. Automatic uses the direction that preserves both rims' face winding. Use the explicit matching direction to pin that choice. An incompatible choice shows the source mesh and disables Apply.
- **Offset** cycles the target correspondence by one vertex per step, starting from the pairing with the smallest total squared distance. An offset can twist or intersect the surface. Try another offset if the preview rejects it.
- **Segments** sets the number of equally spaced strips from 1 to 8. Type a value, use the field's step buttons, or middle-drag a number or its label. Right-click a numeric field for **Lock** and **Unlock**. Escape or pointer cancellation during a middle-drag restores its starting value.
- **Apply Bridge** or Enter in a Bridge number field commits the mesh in one undo step. **Cancel Bridge** or Escape restores the source mesh and selection. The original rim IDs remain selected after Apply. Save the joined geometry in a regular MSB scene.

Bridge supports two disjoint, strictly convex loops in separated parallel planes in one polygon mesh. The loops need equal counts of 3 to 32 edges. The mesh can contain up to 4,096 vertices and 4,096 face corners. The loops can belong to one connected shell or separate shells of that mesh. Skinned meshes, blend shapes, imported normals, UVs, textured materials, nonmanifold topology and bridge faces that fold, intersect, or lose precision in the viewport are rejected. Source faces and vertices retain their IDs and values. Each new strip inherits the material from the adjacent face at its source edge. The canonical source loop starts with the lexically first boundary vertex ID, independent of pick order. Normals use the mesh's existing Flat or Smooth shading.

Musubi follows Maya's same-mesh border-edge workflow in its docked **Edit Topology** controls. **Segments** corresponds to Maya's Divisions and **Offset** shifts correspondence one vertex at a time. Musubi previews a linear polygon strip with explicit Apply and uses the same keyboard focus, middle-drag, and viewport selection behavior as Bevel. Open `examples/modeling/mesh-bridge.msb` and select the inner rims of **Open cylinder sections** or **Separated open boxes**. Both fixtures use single-sided materials, so a strip with incorrect winding would disappear from the outside. You can regenerate the scene with `node scripts/create-mesh-bridge-example.mjs`.

The boundary traversal, linear interpolation, and triangle separation checks are original code using the project's existing topology validator, tessellation, preview renderer and Three.js 0.180.0 (MIT). The example has original procedural geometry and no external assets.
